# 从模块思路到可验证接入

## 先确认对象层级

机制、层、块、骨干、训练策略和完整任务框架是不同层级。替换一个SE门控，与把骨干换成ViT-Adapter、把检测器换成DINO的改动范围不同。先问候选解决哪个失败环节，再确定最小改动；整网络结果不能作为其中一个子块的贡献证据。

通过 `search_catalog.py --inspect CODE-ID --json` 读取静态接口。构造函数的默认值不是任务推荐值，演示输入也不是唯一支持形状。仅返回权重的TA、返回多尺度列表的骨干和返回分类logits的网络，不能直接替换同形状特征块。

## 张量语义表

| 表示 | 常见含义 | 接入前必须确定 |
|---|---|---|
| B,C,H,W | 二维卷积特征 | 通道数、分辨率、stride、padding |
| B,H,W,C | 通道末轴网格 | LayerNorm/GRN归一化轴，permute开销 |
| B,N,C | token序列 | N是否含特殊token，N与H×W的对应 |
| B,C,D,H,W | 三维体特征 | 体素间距、各向异性、3D算子 |
| B,T,C,H,W | 时间步或脉冲序列 | T不是Conv3d通常意义的空间深度；看实现如何使用 |
| B,L,C | 多变量时序 | 历史长度、特征轴、预测长度、因果性 |
| B,N,3 + B,C,N等 | 点坐标与点特征 | 坐标系、邻域索引、点序与掩码 |

从B,N,C恢复H/W需要真实网格元数据；不能凭开平方猜一个正方形，更不能把N,C顺序直接reshape成图像。`permute`改变轴顺序，`reshape`改变张量组织，两者不互相替代。额外检查特殊token、patch顺序、非连续张量及奇数分辨率。

## 融合和重采样

- sum通常需要完全相同的形状；concat后的投影会改变参数量。双输入门控前先核实每路通道、分辨率与空间坐标。
- `interpolate`、`grid_sample`、转置卷积和pixel shuffle有不同坐标和padding约定。比较边界时固定align_corners等设置，不能把半像素偏移解释成方法贡献。
- DySample的lp和pl路径都是上采样。它们的差别需看投影与重排次序，不能按注释认定pl是下采样。`groups`和`scale²`存在通道整除条件。
- HWD拼接低频及方向高频子带，投影前通道增加；需要检查小波库、奇数尺寸边界和目标输出宽度。
- 模态融合不自动完成几何配准。受控位移下性能下降时，先区分特征选择和真正的对齐机制。

## 已确认的本地实现风险

| 对象 | 静态观察 | 使用前的决定 |
|---|---|---|
| EnhancedPartialConv2d | forward路径新建卷积；局部参数未作为持久子模块注册 | 优先寻找可信原实现；如获授权修代码，把可学习层移到初始化，并测重复前向、梯度和设备一致性 |
| GRN | 参数为1,1,1,C，空间范数在轴1、2 | 该版本输入是NHWC；NCHW要显式转换或重写对应轴 |
| RevIN | 特征在最后一维，归一化统计作为实例状态 | norm/denorm必须对应同批历史输入，不能被另一批覆盖；不得用未来真值统计 |
| MDTA | 每个head在通道维形成注意力矩阵 | 不是HW×HW空间全局亲和；检查C整除head数 |
| MLAttention简化版本 | softmax后施加mask且未再归一化；Fast版本有未用参数 | 检查padding长度敏感性；不能当作完整标签树分类器 |
| GAU文件的TA子块 | 返回池化响应，定义的sigmoid未在forward调用 | 先确定返回权重还是特征，不能直接替换完整时空编码器 |
| 3个代码单元 | 完整静态语法解析失败 | 默认检索排除，回读来源定位问题；不宣称已可运行 |

静态扫描只能提示风险。例如`.cuda()`可能仅出现在演示部分，不说明主模块一定只能在GPU运行。代码里没查出问题也不证明可训练。

## 成本与训练检查

二维普通卷积的主要乘加随 `B·Hout·Wout·Cout·(Cin/groups)·Kh·Kw` 变化；深度卷积后逐点混合仍需计算逐点投影成本。常规空间注意力的亲和存储随token数平方变化，但压缩键值、窗口、通道转置和特定优化实现具有不同成本，须按实际路径分析。

参数少、FLOPs低、显存低和端侧延迟低是四件事。报告输入尺寸、batch、精度、设备、推理框架、预热与计时方式；动态采样、频域算子、unfold/gather及数据布局转换都可能主导真实延迟。训练容量与推理结构重参数化的收益也分开报告。

获得实现/训练授权后，再做有意义的小规模验证：奇偶尺寸、最小通道、零/常量输入、掩码、CPU/目标GPU、训练与eval、梯度到达各分支、优化器能否看到新增参数。测试围绕候选的实际风险设计，不强制所有任务跑全套。

机制测试随后进行：只改一个接入点，固定训练与数据；选一个相同预算的简单替代；预先确定失败样例分桶、主要指标和停止条件。先多模块叠加、后倒推故事会使贡献难以归因。
